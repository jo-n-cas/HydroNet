# HydroNet UI plan

Status: draft for approval, revision 2 (Amstel-only focus).

## 0. Spatial focus: the Amstel river only (decided)

The UI is scoped to the **Amstel corridor**: the river from Amstelhoek/Uithoorn to Amsterdam centre, plus a configurable buffer (25/50/100 m, default 100 m, matching the pipeline rule in `docs/AMSTEL_STATION_SELECTION.md`). Consequences for the plan below:

- **Map:** the default extent is the corridor. Only corridor stations are drawn as data markers. Stations outside the corridor are hidden by default; an optional "context" toggle shows them as tiny grey dots without counts.
- **Area selection:** a **chainage range slider** (km along the river) replaces the map rectangle. It selects a stretch of the river and drives the small-multiples strip, the corridor view and the phosphorus chain. Choosing a stretch along a one-dimensional river is more natural than a 2-D brush.
- **RWZIs:** the primary set is the plants linked to the Amstel: those within the pressure buffer of the corridor, plus Uithoorn, De Ronde Venen and Amstelveen, which sources link to the Amstel. That list is in `config/settings.yaml` and tagged ASSUMED until discharge points are verified. The other AGV plants are shown only in a collapsed "Rest of AGV (context)" section on the Pressures page.
- **Overview and Data gaps:** every count is shown twice, as **Amstel corridor** and **AGV-wide**. This makes the sampling story ("how much of AGV's monitoring is on the Amstel") explicit.
- **Biology:** only 1 of the 50 raw-biology locations lies on the Amstel (VGD125, 63 m from the centreline, km 12.3), so it disappears at the 25 / 50 m buffer settings. In that case the biology panels show an empty state that explains this ("0 of 50 raw-biology locations within 50 m of the Amstel"), and the phosphorus chain shows VGD125 with its distance, tagged ASSUMED. Biology from further away is never shown as if it were on the river.
- **The Amstel line is required.** It is not in the data, and the colleague's `amstel_water_quality_map.html` does not contain it (it holds station points, the parameter list, metadata for the 50 sites and monthly hydrology series only). Until an approved open-data source is downloaded, the fixtures use a synthetic line.
- This narrows instructions Sections 1 and 6, which describe an AGV-wide coverage map. The change is logged in `docs/DECISIONS.md`, and instructions Section 6 will be updated to match. Scope: `app/streamlit_app.py`, `app/pages/`, `app/components/`, the pure view logic in `src/hydronet/views/`, and the synthetic fixtures. The data pipeline (cleaning and merging) is built in parallel by colleagues; the UI only reads its outputs.

## 1. Data contract and data source switch

The UI reads only processed files. Their paths come from `config/settings.yaml`:

```yaml
ui:
  data_dir: tests/fixtures/processed   # switch to data/processed for real data (one line)
```

When `data_dir` points to the fixtures, every page shows a persistent banner: "Synthetic fixture data: for layout testing only, not AGV data". Fixture station IDs are prefixed `SYN`, so a fixture value can never be mistaken for a real one.

The fixtures are generated by `scripts/make_ui_fixtures.py` (seeded, re-runnable). They have exactly the schemas from the instructions, Sections 5.1–5.6:

| File | Schema (from instructions) | Used by pages |
|---|---|---|
| `stations.parquet` (GeoParquet) | `station_id, is_chem, is_bio, has_raw_bio, n_chem_obs, n_bio_obs, n_parameters, krw_watertype, eag, krw_waterbody, geometry` | 1, 2, 3, 4, 6 |
| `coverage.parquet` | `station_id, source, parameter, n_observations, NAME, UNIT, GROUP` | 2, 3, 4, 6, 7 |
| `bio_values.parquet` | `station_id, sample_id, datetime, parameter, taxon, taxon_group, value, unit, limit_flag, quality_code, qa_flag` | 3, 6 |
| `hydrology.parquet` | `sensor_id, site, date, quantity, value, qa_flag` | 4, 6 |
| `rwzi_effluent.parquet` | `installation, installation_name, measurement_point, date, product, quantity, parameter, unit, value` | 5, 6 |
| `amstel_stations.parquet` | `station_id, distance_to_river_m, chainage_m` | 2, 3, 4, 6 |
| `rejected_values.parquet` | source columns + `reason` | 7, 8, "About this view" |

Additional inputs the UI needs. Points 3 and 4 are **proposals that need agreement with the pipeline team**:

1. `config/parameter_groups.yaml`: the tiers from Section 1.1 (I will write it, since it is config, not data).
2. `config/rwzi_locations.csv` and `data/external/amstel.geojson`: synthetic versions in the fixtures. The real ones need the user's approval before any download. The colleague's `amstel_water_quality_map.html` (approved for reuse) has no river geometry; I reuse its popup layout (counts per parameter, metadata for the 50 sites, sampled years) and its chemistry/biology marker encoding.
3. **Proposal:** `pipeline_manifest.json` in `data_dir`, holding the pipeline run date, input files and row counts before and after cleaning per output. "About this view" reads it. If it is missing, the panel says so rather than guessing.
4. **Proposal:** the buffer-sensitivity counts (25/50/100 m) are computed in the UI from `stations.parquet` plus the Amstel line. This is cheap with geopandas and avoids an extra pipeline output.

```
  corridor.py               # chainage ordering, proximity links, buffer sensitivity
  timeaxis.py               # dataset spans, overlap period
  pressures.py              # yearly RWZI summaries, gap detection (plant x parameter)

```

The UI code stays thin: pages call `views.*` functions and `components.*` renderers only.

## 3. Global controls (sidebar, stored in `st.session_state`)

Each control has a one-line help text. The current values are echoed under every figure.

| Control | Default | Help text |
|---|---|---|
| Station source | both | "Which inventory to show: chemistry, biology or both." |
| Parameter group | Tier 1 nutrients | "Groups from Section 1.1; Tier 1 is the approved focus." |
| Parameter | `Ptot_mgP/l` | "Single parameter within the group, or all." |
| Date range | full span | "Filters biology, hydrology and RWZI series; coverage counts have no dates." |
| Amstel buffer | 100 m (25 / 50 / 100) | "Distance from the river centreline used to select corridor stations." |
| Quality code filter | all codes shown | "Biology quality codes (0, 3, 9); code meanings not confirmed, so nothing is hidden by default." |
| Selected station | none | Set by a map or corridor click; shared across pages. |

## 4. Shared components

- **Analysis-settings caption:** one small line under each figure, e.g. `Settings: group=Tier 1 nutrients · parameter=Ptot_mgP/l · buffer=100 m · dates=2021-01-01–2024-12-31 · quality codes=all · data=processed (run 2026-10-28)`.
- **n-line:** every figure states `n = X observations · Y locations · date span`.
- **Tags:** `OBSERVED` (solid hairline box) and `ASSUMED / INDICATIVE` (dashed box, italic). Ordering along the river, RWZI plant location versus discharge point, and overlap periods are always tagged ASSUMED.
- **Causation note:** a quiet persistent line, "Association shown, not causation. Proximity or co-occurrence does not show that one affects the other." It appears on every juxtaposition view (pages 2, 4, 5 and 6).
- **About this view:** an expander showing source files, processing steps, rows before and after cleaning, rejected rows by reason, and the pipeline run date. It has an Export button for the figure table (CSV) and for the settings plus provenance (JSON).
- **Empty state:** names the reason and what would fill it, e.g. "No raw chemistry values: the prototype has FYCHEM counts only. Filled by the raw FYCHEM export (see Data gaps)."

## 5. Visual system

- Background `#FAF8F3`, text `#1A1A1A`, hairlines `#D9D5CC`. Titles in a serif (Source Serif via Google Fonts, with a Georgia fallback; no download needed, the CSS falls back offline). UI and labels in system sans (Inter / -apple-system).
- Counts use a viridis sequential scale; zero is grey `#BDBDBD`; the accent is `#C2410C` (burnt orange), used only for the selection and highlights.
- Marker shapes: chemistry = circle, biology = square, both = diamond. The 50 raw-biology stations get an accent ring. Size encodes the count (sqrt scale), and the scale is printed in the map caption.
- Flagged values are hollow markers with an `x`. Values with a limit symbol `<`/`>` are drawn as triangles pointing in the limit direction. Values with quality code 3 or 9 are drawn at reduced opacity, with the code shown in the hover.
- Overlap periods are a light grey band on any shared time axis, with a direct label, e.g. "overlap 2021–2024 (ASSUMED comparable)".
- Charts use a Plotly template with no gridline clutter, direct labels instead of legends, and units in axis titles. Small multiples use shared axes, so they are identically scaled. Tables use `st.column_config.BarChartColumn` / `LineChartColumn` for sparklines.
- Accessibility: contrast is checked to be at least 4.5:1, every figure gets a text caption as alt text, and only native Streamlit widgets are used, so controls stay keyboard-accessible.

## 7. Tests (pytest, `tests/test_views_*.py`)

- Coverage aggregation: per group, per station, per area (bounds filter); unknown codes go to `other`.
- Chainage ordering: stable, upstream to downstream; ties are broken by `station_id`.
- Proximity links: within a buffer only, and the distance is correct.
- Buffer sensitivity: monotone counts (25 ≤ 50 ≤ 100), with entering and leaving stations listed.
- Overlap period: two or more spans, no overlap returns `None`, and open or invalid spans are handled.
- RWZI yearly summaries and the gap matrix, including a plant with no phosphate.
- Data-gaps table: ratios, and the PFAS / medicines gap labels.
- Fixture schema test: fixtures match the column contract, so switching to real files fails loudly if the schemas diverge.
